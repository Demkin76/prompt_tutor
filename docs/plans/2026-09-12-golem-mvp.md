# GOLEM MVP — Implementation Plan (hackathon, 2–3h)

Decisions (from user, 2026-09-12):
- Modes: **Maze**, **Red Floor**, **Tower Defense (PvE)**. One grid engine, mode-specific rules.
- Progression: one charter runs **3 levels of the current tier**; passing all 3 unlocks the next tier. Rating = tiers/levels passed, tie-break: shorter charter, fewer ticks, fewer LLM calls.
- Deterministic opponent only in Tower Defense; its "charter" (rules) is shown to the player before writing their own. Tower limit per level. Player charter decides tower placement.
- Hosting of the agent loop: **Daytona sandbox** runs `runner.js` (sim + LLM loop), streams ticks/events into **Convex** via HTTP mutations. Fallback: same loop in-process in a Convex action when `DAYTONA_API_KEY` is absent.
- LLM: x.ai `grok-4-fast` (configurable via `XAI_MODEL`), JSON-schema structured output.
- UI: Vite + React + TS, Canvas 2D, English, placeholder colored tiles keyed by `assetKey`, 32×32 tiles. No auth: `sessionId` in localStorage.
- Prompt budget grows with tier (per-level `promptBudget`).
- Work on `main`, commit per task.

## Layout
```
package.json            (single npm project, workspaces not used)
src/core/               pure deterministic engine (no deps): types, rng, grid, generators, sim, observation, verifiers, scoring, levels
src/runtime/            agent runtime: prompt assembly, LLM client (x.ai), decision schema/validation, episode loop
src/runner/             entry bundled by esbuild into a single JS string for Daytona; talks to Convex over HTTP
convex/                 schema, queries/mutations, actions (startRun → Daytona or in-process)
app/                    Vite React UI (src/app)
scripts/build-runner.mjs  esbuild → convex/_runner/bundle.ts (exports RUNNER_SOURCE string)
```
